

# 1. Where it should live

Like Ansible, the best place is **user-scoped, hidden config in home directory**:

```text
~/.satrc
```

or if you want a folder-based system (more scalable):

```text
~/.sat/
  config.yml
  templates/
  rules/
```

------

# Recommendation (cleanest long-term)

👉 Use:

```text
~/.sat/config.yml
```

because:

- structured (YAML)
- extensible
- works well with DataLad + scripts
- easy to version later if needed

------

# 2. What it should contain

Minimal SAT config would define:

------

## A. Repository root conventions

```yaml
repository_root: "~/repositories"
default_repository_name: "repository"
```

------

## B. Semantic container structure

```yaml
entity_structure:
  files:
    index: "index.md"
  folders:
    assets: "assets"
    meta: "meta"
```

------

## C. Language model (important for you)

```yaml
languages:
  default: "en"
  supported:
    - en
    - fr
```

------

## D. Naming rules

```yaml
naming:
  entity_mode: "folder"
  allow_duplicate_names: true
  scope: "path_based"
```

------

## E. DataLad integration

```yaml
datalad:
  use_subdatasets: true
  auto_save: false
  annex_assets: true
```

------

## F. Template system (your “entity factory” idea)

```yaml
templates:
  entity:
    path: "~/.sat/templates/entity"
```

------

# 3. What this gives you conceptually

You move from:

> ad-hoc folder conventions

to:

> a **controlled semantic filesystem system**

BUT still:

- not enforced by DataLad
- enforced by your tooling

------

# 4. Important design insight

This is the key distinction:

> DataLad = execution layer
> SAT config = behavioural layer
> filesystem = structural layer

------

# 5. Minimal version (if you want to start small)

```yaml
repository_root: "~/repositories"

entity_structure:
  index: "index.md"
  assets: "assets"
  meta: "meta"
```

That alone already gives you consistency.

------

# Bottom line

- Put it in: `~/.sat/config.yml`
- It defines **your semantic rules, not DataLad rules**
- It becomes the “Ansible config equivalent” for your archive system
