# Using ASD-STE100 - What it is and how it works

**ASD-STE100** is the **ASD Simplified Technical English specification**—an international controlled-language standard designed to make technical documentation easier to understand, translate, and maintain.

It is particularly common in **aerospace, defence, manufacturing, maintenance, and other safety-critical technical environments**.

### The basic idea

ASD-STE100 restricts and standardizes how technical English is written. It does **not** try to make English simpler by removing technical concepts. Instead, it controls the **language used to express those concepts**.

For example, instead of:

> Ensure that the unit is functioning correctly prior to commencing the operation.

you might write:

> Make sure that the unit operates correctly before you start the operation.

The specification provides rules for things such as:

- **Vocabulary** — use approved words with controlled meanings.
- **Sentence structure** — keep sentences short and grammatically simple.
- **Verb usage** — prefer specific, direct verbs over nominalizations.
- **Consistency** — use the same term for the same concept.
- **Instructions** — make actions and their conditions explicit.
- **Ambiguity** — avoid wording that can have multiple interpretations.
- **Warnings and cautions** — use standardized structures.
- **Technical terminology** — domain-specific terms can still be used when necessary.

### Why it matters

One of the particularly interesting aspects of ASD-STE100 is that it was designed not only for **human readers**, but also to improve **translation and information reuse**.

Controlled language can reduce:

```
ambiguity
   ↓
misinterpretation
   ↓
translation difficulty
   ↓
maintenance cost
```

This becomes especially valuable when documentation is:

- translated into many languages,
- maintained over decades,
- shared between organizations,
- consumed by people with different levels of English proficiency,
- used for maintenance or safety-critical procedures.

### ASD-STE100 isn't "plain English"

That's an important distinction.

**Plain language** generally asks:

> How can we communicate this information clearly to the intended audience?

**ASD-STE100** asks something closer to:

> How can we express technical information using a controlled, standardized subset of English that minimizes ambiguity and supports consistent translation?

So ASD-STE100 is considerably more prescriptive.

### Where it fits with accessibility

There is a useful relationship between **ASD-STE100, plain language, and accessibility**, although they are not interchangeable.

For example:

```
                 Clear communication
                        │
          ┌─────────────┴─────────────┐
          │                           │
     Plain language             Controlled language
          │                           │
          │                      ASD-STE100
          │                           │
          └───────────┬───────────────┘
                      │
              Easier comprehension
                      │
              Better translation
                      │
             Better information reuse
```

For a highly accessible website or CMS, some **ASD-STE100 principles** could therefore be very useful even if you don't attempt full compliance with the specification.

In particular, I think the principles of **controlled vocabulary, consistent terminology, short sentences, explicit relationships, and avoidance of ambiguity** fit very well with the kind of accessible, multilingual content architecture you've been working on.

The official specification is maintained by **ASD-STAN (AeroSpace and Defence Industries Association of Europe)** and is currently known as **ASD-STE100 Simplified Technical English**.
